## 3. 待办方向：在等什么、为什么停（核心章节）

### A. deepseek-flash 识图 bug —— **唯一活跃 bug，建议新对话第一件事处理**

- **现象**：用户发表情包图片，弥娅回复"图片内容我看不到"。日志证据：`2026-09-20 15:13:54 开始分析图片(166.6KB jpeg)` → `API返回结果:`（**空**）。
- **疑似根因**（未验证）：DeepSeek V4.1 是思考型模型，视觉调用可能把 token 预算耗在 reasoning 上——`deepseek_vision` 配置 `max_tokens: 1500` 可能被思考耗尽导致 content 为空；且 `multi_vision_analyzer._call_vision_api` 只读 `message.content`，**没有读 `reasoning_content` 兜底**（主链路 ai_client 有此处理，视觉路径没有）。
- **修复方向**：①视觉调用读 reasoning_content 兜底；②max_tokens 提到 3000+；③调研 DeepSeek API 是否支持关闭思考（类似 `thinking: disabled` 参数）；④修复后用同一张表情包回归。
- **为什么停**：用户反馈"识别表情包有 bug"后即转入本文档编写，尚未开始修复。
- **验收**：同一张表情包能产出场景级描述（对标 9/12 glm 的"黑白卡通表情包+四黑色大字"水准）。
