## 二、记忆类人化增强（核心 5 项已落地，以下为第二梯队）

### 2. 睡眠期记忆巩固 【优先级：中 · 中等成本】

| 项 | 说明 |
|---|---|
| 功能 | 模拟人类睡眠时大脑整理记忆：弥娅在空闲时段（如深夜无消息时）自动整理白天记忆——相似记忆合并、重要信息升级长期记忆、生成每日情节摘要。记忆库越用越干净，检索越来越准 |
| 已有基础 | `memory_enhancer.refine_long_term_memories()`（相似记忆合并）**已写好但未接线**；`store_daily_summary()`（每日摘要入库）已存在；`hub/scheduler` 定时任务框架可挂载 |
| 实现思路 | 注册一个低频定时任务（每天 1 次，凌晨触发）→ 取当日对话记忆 → 调用 refine 合并去重 → LLM 生成当日摘要 → store_daily_summary 入库 |
| 成本 | 每天 1 次 LLM 调用（摘要用便宜模型可控）；开发量约 1~2 天 |
| 风险 | 合并逻辑误删有效记忆 → 需先在合并前做备份（backups 目录机制已有） |

### 3. 主动分享往事 【优先级：中 · 中等成本】

| 项 | 说明 |
|---|---|
| 功能 | 从"你问她还记得吗"升级为"她主动说：诶，我突然想起上周你……"。像真人一样在聊到相关话题或情绪到位时，主动翻出共同回忆分享 |
| 已有基础 | 主动聊天系统（proactive_chat，45s/300s 轮询）已上线；`cognitive_engine` 联想召回已打通（含 memory_links 一跳关联） |
| 实现思路 | 在主动聊天触发链路中增加"往事分享"分支：取近期话题关键词 → 检索/联想出高情绪或高重要性的旧记忆 → 经措辞模板包装后主动发出；需设计触发时机（话题相关度 + 情绪匹配 + 距上次分享的冷却时间） |
| 成本 | 复用现有 LLM 调用链路，增量费用小；开发量约 2~3 天（主要是时机策略打磨） |
| 风险 | 时机拿捏不当会显得突兀/重复 → 必须做配置开关（如 `proactive_share.enabled`）与冷却机制，灰度观察 |

### 4. 统一 LLM 事实抽取 【优先级：低 · 持续成本】

| 项 | 说明 |
|---|---|
| 功能 | 现状记忆提取靠多套规则（触发词、正则、五元组各走各的，召回质量参差）。改为每轮对话用一次统一 LLM 调用抽取"值得记住的事实"（如"用户养了只猫叫咪咪"），结构化入库，记忆质量最高 |
| 已有基础 | `should_remember()` 规则触发链路已稳定；GRAG 五元组提取已有 LLM 调用与解析框架（`_extract_quintuples_sync`），可共用调用/合并 prompt 一次抽两种结构 |
| 实现思路 | 在对话链路尾部增加统一抽取步骤（用 simple_chat 档便宜模型）→ 输出结构化事实 JSON → 按现有 store 入口入库（带情绪/重要性字段）；逐步替换规则触发的 `_extract_memory_fact` |
| 成本 | **每轮对话 +1 次 LLM 调用 = 持续 API 费用**（用 deepseek-v4-flash 档可控）；开发量约 2~3 天 |
| 风险 | 抽取质量依赖模型；需配抽取频控（非每轮必抽）与费用开关 |

## 三、其他遗留事项

### 5. data/neo4j 归档清理 【优先级：高 · 零开发量 · 等确认】

- **现状**：`data/neo4j/` 共 517MB（514MB 为事务日志），真实图数据仅 94 条五元组 <1MB；图谱已 SQLite 化，该目录成为死数据，部署服务器时无需携带。
- **两个方案**：① 直接归档到仓库外后删除（旧知识不保留）；② 先写一次性导入脚本把 94 条五元组灌入 `graph_store`（弥娅继续"记得"这些旧知识）再删。
- **阻塞点**：删除属破坏性操作，等然鑫拍板选哪个方案。

### 6. memory/ 目录 black 格式化 【优先级：低 · 独立小 PR】

- `memory/` 下 14 个文件历史上未做 black 格式化（多为老代码），CI 不检查该目录。
- 正确做法：单独开一个"纯格式化"提交跑 `black memory/`，与功能改动严格分离，避免污染 diff 审查与 git blame。

### 7. Neo4j 双后端抽象 【优先级：低 · 仅未来真需要图数据库时】

- 当前 graph_store（SQLite 一跳查询）已覆盖现有用例；若未来出现多跳遍历/图算法需求，再考虑抽象 `GraphBackend` 接口让 SQLite/Neo4j 可切换。现在做是过度设计。

### 8. 启用真实 Embedding 语义检索 【优先级：低 · 可显著提升检索质量】

- **现状**：`cognitive_engine` 的 embedding_client 为 None，语义相似度分量（权重 0.35）实际走伪向量回退，检索主要靠关键词+标签。
- **实现思路**：接入云端 embedding API（SiliconFlow/智谱，按量 ~0.001 元/千 token，零内存占用）；`multi_model_config.json` 的 `embedding_config` 字段已有加载逻辑，配置即用；存量记忆需批量补算向量。
- **收益**：语义级"想起来"（用户换个说法也能命中记忆），配合 A2 衰减/联想召回效果更佳。
