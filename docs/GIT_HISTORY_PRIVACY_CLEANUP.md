# Git 历史隐私清理方案（未执行）

当前分支已将 `config/permissions.json`、`config/qq_config.yaml` 和 `miya_frontend/data/` 从 Git 索引移除，本机文件保留。此操作只能保护后续提交，不能删除旧提交、远端分支、标签或缓存里的副本。

2026-09-27 的本地只读盘点：上述路径在全部本地引用中涉及 179 个历史对象、22 个提交；仓库还有多条远端分支和一个标签。仓库约 2 GiB。历史源代码中也曾出现真实账号标识，因此仅按路径过滤并不能完成清理。

执行历史改写前需要所有仓库协作者约定停推时间，并保留一份离线、访问受限的完整镜像备份。先完成并提交当前工作树，再在**独立镜像克隆**中用 `git-filter-repo` 删除上述路径，并审查历史中其他含私有账号或凭据的文件。必要时用替换规则清理标识，但应逐项复核，避免破坏非敏感代码。不要在当前带有未提交修改的工作树中运行过滤器。

验证应覆盖所有分支与标签：敏感路径不再出现在 `git rev-list --all --objects` 的输出；抽检旧提交不再包含需清理的账号或凭据；新克隆可以构建并通过测试。随后由仓库维护者统一强制更新远端分支和标签，通知协作者重新克隆或重置本地分支，并检查 Pull Request 引用及托管平台缓存。凡已公开过的真实密钥仍应轮换；历史改写不能让已被复制的内容失效。

这一步会改变提交哈希并影响所有克隆和开放中的 Pull Request，须在明确的维护窗口执行。
